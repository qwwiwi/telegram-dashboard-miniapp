# Postgres и свой Supabase вместо SQLite

Этот файл – про один шаг: перенести базу дашборда из файла SQLite в PostgreSQL. Код каркаса из `starter.md` остаётся тем же. Меняется один модуль (`app/db.py`) и несколько строк рядом. Если переменная `DATABASE_URL` не задана, дашборд работает на SQLite, как раньше.

Supabase – это набор сервисов вокруг PostgreSQL. Его можно поставить на свой сервер из открытого кода. Для дашборда нужна только база внутри него. Остальное (вход пользователей, файлы, API) дашборду не нужно, но не мешает.

## 1. Когда это нужно

Для личного дашборда SQLite хватает. Выбирайте Postgres, если верно хотя бы одно:

- владелец хочет смотреть и править таблицы в окне Supabase Studio, а не командами;
- в базу пишут несколько программ с разных машин, а не один сервер;
- к базе нужен прямой доступ нескольким людям или сервисам;
- нужны привычные для Postgres копии и восстановление;
- Supabase на сервере уже есть для другого проекта.

Что вы получаете взамен: ещё одна служба, которую надо обновлять и копировать. По официальной инструкции Supabase в Docker просит минимум 4 ГБ памяти и 40 ГБ диска (рекомендует 8 ГБ и 80 ГБ). Это проверено 11.11.2026 на странице https://supabase.com/docs/guides/self-hosting/docker. Если сервер слабее, ставьте обычный Postgres или оставьте SQLite.

## 2. Как это устроено в коде

- Весь SQL в проекте остаётся написанным один раз, в стиле SQLite (`?`, `datetime('now')`, `ON CONFLICT`).
- Модуль `app/db.py` даёт класс `Db`. Для Postgres он сам заменяет `?` на `%s` и `datetime('now')` на то же время в UTC в том же текстовом виде.
- `INSERT OR IGNORE` заменён на `INSERT ... ON CONFLICT ... DO NOTHING`: эта запись работает в обеих базах.
- Таблицы и колонки те же. Дни (`day`) и отметки времени остаются текстом `YYYY-MM-DD` и `YYYY-MM-DD HH:MM:SS`. Поэтому код и данные переезжают без пересчёта.
- Драйвер – `psycopg` версии 3 (пакет `psycopg[binary]`). Почему он: это нынешний драйвер Postgres для Python, у него есть готовая сборка без компилятора, и он не требует правок в остальном коде. Он ставится отдельно, только когда нужен.
- Строки результата читаются и по номеру (`row[0]`), и по имени (`row["key"]`), как в SQLite.
- `with conn:` – одна транзакция: подтверждение при успехе, откат при ошибке. Соединение она не закрывает.

Разница типов. Именно из-за неё нельзя просто «поменять строку подключения»:

| SQLite | PostgreSQL в этом каркасе | Почему |
|---|---|---|
| `INTEGER PRIMARY KEY` (id) | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | автонумерация; при переносе старые номера сохраняются |
| `tg_id INTEGER` | `BIGINT` | Telegram-id бывают больше 4 байт, `INTEGER` в Postgres их не вместит |
| `REAL` | `DOUBLE PRECISION` | `REAL` в Postgres – 4 байта и теряет точность; `REAL` в SQLite – 8 байт |
| `TEXT` для дней и времени | `TEXT` в том же формате | запросы и код не меняются |
| `datetime('now')` | `to_char(now() AT TIME ZONE 'UTC', 'YYYY-MM-DD HH24:MI:SS')` | тот же текст, то же UTC |
| `?` | `%s` | делает `Db` |
| `PRAGMA ...` | не нужно | настройки файла SQLite |

Если позже понадобятся настоящие типы `DATE` и `TIMESTAMPTZ`, это отдельная правка: запросы и код чтения дат придётся менять вместе со схемой.

```python
"""Storage layer: SQLite file by default, PostgreSQL when DATABASE_URL is set. One short-lived connection per request.

All SQL in the project is written once, in SQLite style (``?`` placeholders, ``datetime('now')``, ``ON CONFLICT``).
``Db`` translates the two differences for PostgreSQL, so no other module knows which database is behind it.
"""

from __future__ import annotations

import sqlite3
from collections.abc import Iterable
from pathlib import Path
from typing import Any

from app.metrics import STORED

# SQLite: the original schema.
SCHEMA_SQLITE = """
CREATE TABLE IF NOT EXISTS allowed_users (
  tg_id INTEGER PRIMARY KEY,
  name TEXT NOT NULL DEFAULT '',
  added_at TEXT NOT NULL DEFAULT (datetime('now')),
  revoked_at TEXT
);
CREATE TABLE IF NOT EXISTS metric_defs (
  key TEXT PRIMARY KEY,
  department TEXT NOT NULL,
  title TEXT NOT NULL,
  unit TEXT NOT NULL CHECK (unit IN ('count', 'money', 'percent')),
  kind TEXT NOT NULL CHECK (kind IN ('sum', 'balance'))
);
CREATE TABLE IF NOT EXISTS metric_values (
  key TEXT NOT NULL REFERENCES metric_defs(key),
  day TEXT NOT NULL,
  dim TEXT NOT NULL DEFAULT '',
  value REAL NOT NULL,
  source TEXT NOT NULL,
  updated_at TEXT NOT NULL DEFAULT (datetime('now')),
  PRIMARY KEY (key, day, dim)
);
CREATE INDEX IF NOT EXISTS metric_values_day ON metric_values(day);
CREATE TABLE IF NOT EXISTS ingest_keys (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  key_hash TEXT NOT NULL UNIQUE,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  revoked_at TEXT,
  last_used_at TEXT
);
CREATE TABLE IF NOT EXISTS ingest_log (
  id INTEGER PRIMARY KEY,
  at TEXT NOT NULL DEFAULT (datetime('now')),
  key_name TEXT NOT NULL,
  source TEXT NOT NULL,
  rows INTEGER NOT NULL
);
"""

# PostgreSQL: the same tables and columns. Days and timestamps stay TEXT in the same format as in SQLite
# ('YYYY-MM-DD', 'YYYY-MM-DD HH:MM:SS' in UTC), so the code and the data move between the two without conversion.
# REAL would be 4 bytes in PostgreSQL (SQLite's REAL is 8): DOUBLE PRECISION is the equivalent.
# tg_id is BIGINT: Telegram ids do not fit into 4 bytes.
PG_NOW = "to_char(now() AT TIME ZONE 'UTC', 'YYYY-MM-DD HH24:MI:SS')"
SCHEMA_POSTGRES = f"""
CREATE TABLE IF NOT EXISTS allowed_users (
  tg_id BIGINT PRIMARY KEY,
  name TEXT NOT NULL DEFAULT '',
  added_at TEXT NOT NULL DEFAULT ({PG_NOW}),
  revoked_at TEXT
);
CREATE TABLE IF NOT EXISTS metric_defs (
  key TEXT PRIMARY KEY,
  department TEXT NOT NULL,
  title TEXT NOT NULL,
  unit TEXT NOT NULL CHECK (unit IN ('count', 'money', 'percent')),
  kind TEXT NOT NULL CHECK (kind IN ('sum', 'balance'))
);
CREATE TABLE IF NOT EXISTS metric_values (
  key TEXT NOT NULL REFERENCES metric_defs(key),
  day TEXT NOT NULL,
  dim TEXT NOT NULL DEFAULT '',
  value DOUBLE PRECISION NOT NULL,
  source TEXT NOT NULL,
  updated_at TEXT NOT NULL DEFAULT ({PG_NOW}),
  PRIMARY KEY (key, day, dim)
);
CREATE INDEX IF NOT EXISTS metric_values_day ON metric_values(day);
CREATE TABLE IF NOT EXISTS ingest_keys (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  key_hash TEXT NOT NULL UNIQUE,
  created_at TEXT NOT NULL DEFAULT ({PG_NOW}),
  revoked_at TEXT,
  last_used_at TEXT
);
CREATE TABLE IF NOT EXISTS ingest_log (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  at TEXT NOT NULL DEFAULT ({PG_NOW}),
  key_name TEXT NOT NULL,
  source TEXT NOT NULL,
  rows INTEGER NOT NULL
);
"""


def to_postgres(sql: str, has_params: bool) -> str:
    """Rewrite SQLite-style SQL for PostgreSQL: ``datetime('now')`` and ``?`` placeholders.

    A literal ``?`` or ``%`` inside a quoted string is not supported: pass such values as parameters.
    """
    sql = sql.replace("datetime('now')", PG_NOW)
    if has_params:
        sql = sql.replace("%", "%%").replace("?", "%s")
    return sql


class Row(tuple):  # type: ignore[type-arg]
    """A result row readable by position (``row[0]``) and by column name (``row["key"]``), like sqlite3.Row."""

    _names: list[str]

    def __new__(cls, names: list[str], values: Iterable[Any]) -> Row:
        row = super().__new__(cls, values)
        row._names = names
        return row

    def __getitem__(self, item: Any) -> Any:
        if isinstance(item, str):
            return super().__getitem__(self._names.index(item))
        return super().__getitem__(item)


def _row_factory(cursor: Any) -> Any:
    names = [c.name for c in (cursor.description or [])]
    return lambda values: Row(names, values)


class Db:
    """One open connection with the same interface for SQLite and PostgreSQL.

    ``execute`` returns a cursor (iterate it, ``fetchone``, ``fetchall``, ``rowcount``). ``with db:`` is one
    transaction: commit on success, rollback on an error. It does NOT close the connection; call ``close``.
    """

    def __init__(self, raw: Any, postgres: bool) -> None:
        self.raw, self.postgres = raw, postgres

    def execute(self, sql: str, params: tuple[Any, ...] | None = None) -> Any:
        if self.postgres:
            return self.raw.execute(to_postgres(sql, params is not None), params)
        return self.raw.execute(sql, params or ())

    def __enter__(self) -> Db:
        return self

    def __exit__(self, exc_type: Any, exc: Any, tb: Any) -> None:
        if not self.postgres:
            self.raw.__exit__(exc_type, exc, tb)  # sqlite3: commit or rollback, connection stays open
        elif exc_type is None:
            self.raw.commit()
        else:
            self.raw.rollback()

    def close(self) -> None:
        self.raw.close()


def connect(target: Path | str) -> Db:
    """Open the database: a ``postgresql://`` URL (str) or an SQLite file (Path; its folder is created)."""
    if isinstance(target, str):
        try:
            import psycopg  # optional: only needed when DATABASE_URL is used
        except ImportError as exc:
            raise RuntimeError("DATABASE_URL is set, but psycopg is not installed: pip install 'psycopg[binary]'") from exc
        return Db(psycopg.connect(target, row_factory=_row_factory, connect_timeout=5), postgres=True)
    target.parent.mkdir(parents=True, exist_ok=True)
    # FastAPI may open and close a request's connection on different threads; one request uses it at a time.
    conn = sqlite3.connect(target, timeout=5.0, check_same_thread=False)
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA journal_mode=WAL")
    conn.execute("PRAGMA foreign_keys=ON")
    return Db(conn, postgres=False)


def migrate(conn: Db, allowed_ids: Iterable[int]) -> None:
    """Create tables, sync metric_defs with app.metrics, add allowlist ids (a revoked id stays revoked)."""
    if conn.postgres:
        with conn:
            conn.execute("SELECT pg_advisory_xact_lock(7203391)")  # two processes starting at once do not collide
            conn.execute(SCHEMA_POSTGRES)
    else:
        conn.raw.executescript(SCHEMA_SQLITE)
    with conn:
        for m in STORED.values():
            conn.execute(
                "INSERT INTO metric_defs(key, department, title, unit, kind) VALUES (?,?,?,?,?) "
                "ON CONFLICT(key) DO UPDATE SET department=excluded.department, title=excluded.title, "
                "unit=excluded.unit, kind=excluded.kind", (m.key, m.department, m.title, m.unit, m.kind))
        for tg_id in allowed_ids:
            conn.execute("INSERT INTO allowed_users(tg_id) VALUES (?) ON CONFLICT(tg_id) DO NOTHING", (tg_id,))
```

```python
"""Settings from environment variables. Values are never logged."""

from __future__ import annotations

import os
from collections.abc import Mapping
from dataclasses import dataclass, field
from pathlib import Path
from zoneinfo import ZoneInfo


@dataclass(frozen=True)
class Settings:
    """Runtime settings of the dashboard backend."""

    bot_token: str
    session_secret: bytes
    allowed_tg_ids: frozenset[int]
    db_path: Path | None
    tz: ZoneInfo
    currency: str = "₽"
    database_url: str = field(default="", repr=False)  # postgresql://..., empty = SQLite file
    init_data_max_age_s: int = 300  # login must follow the Mini App launch within 5 minutes
    session_ttl_s: int = 12 * 3600

    @property
    def db_target(self) -> Path | str:
        """What ``app.db.connect`` opens: the PostgreSQL URL if set, else the SQLite file."""
        if self.database_url:
            return self.database_url
        if self.db_path is None:
            raise RuntimeError("neither DATABASE_URL nor DB_PATH is set")
        return self.db_path


def load_settings(env: Mapping[str, str] | None = None) -> Settings:
    """Build Settings from a mapping (default: the process environment).

    Raises:
        RuntimeError: a required variable is missing or malformed. The message names variables, never values.
    """
    env = os.environ if env is None else env
    url = env.get("DATABASE_URL", "").strip()
    required = ("BOT_TOKEN", "ALLOWED_TG_IDS", "SESSION_SECRET") + (() if url else ("DB_PATH",))
    missing = [n for n in required if not env.get(n, "").strip()]
    if missing:
        raise RuntimeError("missing settings: " + ", ".join(missing))
    try:
        ids = frozenset(int(x) for x in env["ALLOWED_TG_IDS"].split(",") if x.strip())
    except ValueError as exc:
        raise RuntimeError("ALLOWED_TG_IDS must be comma-separated integers") from exc
    if len(env["SESSION_SECRET"]) < 32:
        raise RuntimeError("SESSION_SECRET must be at least 32 characters")
    if url and not url.startswith(("postgresql://", "postgres://")):
        raise RuntimeError("DATABASE_URL must start with postgresql://")
    return Settings(
        bot_token=env["BOT_TOKEN"].strip(),
        session_secret=env["SESSION_SECRET"].encode(),
        allowed_tg_ids=ids,
        db_path=Path(env["DB_PATH"]) if env.get("DB_PATH", "").strip() else None,
        database_url=url,
        tz=ZoneInfo(env.get("BUSINESS_TZ", "UTC")),
        currency=env.get("CURRENCY", "₽"),
    )
```

```python
def test_storage_differences_between_backends(env: tuple[TestClient, Settings]) -> None:
    """Things that differ between SQLite and PostgreSQL: 8-byte floats, ids above 2**31, rollback, access by name."""
    client, settings = env
    big_id = 5_000_000_000  # a real Telegram id can be this large: INTEGER (4 bytes) in PostgreSQL would overflow
    conn = connect(settings.db_target)
    with conn:
        conn.execute("INSERT INTO allowed_users(tg_id) VALUES (?)", (big_id,))
    assert auth.is_allowed(conn, big_id)
    assert client.post("/api/login", json={"init_data": sign_init_data(big_id, int(time.time()))}).status_code == 200
    day = time.strftime("%Y-%m-%d", time.gmtime(time.time() - 86400))
    h = {"Authorization": f"Bearer {make_key(settings)}"}
    body = {"source": "t", "rows": [{"key": "sales.revenue", "day": day, "value": 1234567.891}]}
    assert client.post("/ingest", json=body, headers=h).status_code == 200
    row = conn.execute("SELECT value, updated_at FROM metric_values WHERE key='sales.revenue'").fetchone()
```

**`tools/sqlite_to_postgres.py`** – разовый перенос данных (раздел 7). Новый файл:

```python
"""Copy a dashboard SQLite database into PostgreSQL (one time, safe to repeat).

Run from the project folder, with the target in the environment:
    DATABASE_URL=postgresql://... python tools/sqlite_to_postgres.py /var/lib/dashboard/dashboard.db
The SQLite file is opened read-only and never changed. Stop the dashboard and the collectors first, so no new rows
arrive during the copy. A repeated run changes nothing (existing rows are kept), and the script prints per-table
row counts of both sides: they must be equal.
"""

from __future__ import annotations

import logging
import os
import sqlite3
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parent.parent))

from app.db import connect, migrate, to_postgres  # noqa: E402

logger = logging.getLogger("sqlite_to_postgres")

# (table, columns, conflict clause). Parents first: metric_values refers to metric_defs.
TABLES: list[tuple[str, list[str], str]] = [
    ("metric_defs", ["key", "department", "title", "unit", "kind"], "ON CONFLICT DO NOTHING"),
    # A revoke made in SQLite must win over the id the new database just got from ALLOWED_TG_IDS.
    ("allowed_users", ["tg_id", "name", "added_at", "revoked_at"],
     "ON CONFLICT(tg_id) DO UPDATE SET name=excluded.name, added_at=excluded.added_at, revoked_at=excluded.revoked_at"),
    ("metric_values", ["key", "day", "dim", "value", "source", "updated_at"], "ON CONFLICT DO NOTHING"),
    ("ingest_keys", ["id", "name", "key_hash", "created_at", "revoked_at", "last_used_at"], "ON CONFLICT DO NOTHING"),
    ("ingest_log", ["id", "at", "key_name", "source", "rows"], "ON CONFLICT DO NOTHING"),
]


def copy(sqlite_path: Path, pg_url: str) -> dict[str, tuple[int, int]]:
    """Copy all tables; returns ``{table: (rows in SQLite, rows in PostgreSQL)}``."""
    src = sqlite3.connect(f"file:{sqlite_path}?mode=ro", uri=True)
    dst = connect(pg_url)
    try:
        migrate(dst, [])  # create the tables and the metric definitions of the current code
        counts: dict[str, tuple[int, int]] = {}
        with dst:
            for table, cols, conflict in TABLES:
                rows = src.execute(f"SELECT {', '.join(cols)} FROM {table}").fetchall()
                sql = f"INSERT INTO {table}({', '.join(cols)}) VALUES ({', '.join('?' * len(cols))}) {conflict}"
                with dst.raw.cursor() as cur:
                    cur.executemany(to_postgres(sql, has_params=True), rows)
            # Rows were inserted with their old ids: move the identity counters past them.
            for table in ("ingest_keys", "ingest_log"):
                dst.execute(f"SELECT setval(pg_get_serial_sequence('{table}', 'id'), "
                            f"COALESCE((SELECT MAX(id) FROM {table}), 1), (SELECT MAX(id) FROM {table}) IS NOT NULL)")
        for table, _, _ in TABLES:
            counts[table] = (src.execute(f"SELECT COUNT(*) FROM {table}").fetchone()[0],
                             dst.execute(f"SELECT COUNT(*) FROM {table}").fetchone()[0])
        return counts
    finally:
        src.close()
        dst.close()


def main(argv: list[str]) -> int:
    """Entry point; returns a process exit code (0 only when every table has the same number of rows)."""
    logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s")
    url = os.environ.get("DATABASE_URL", "")
    if len(argv) != 1 or not url:
        print(__doc__)
        return 2
    if not Path(argv[0]).is_file():
        logger.error("no such SQLite file")
        return 2
    counts = copy(Path(argv[0]), url)
    ok = True
    for table, (a, b) in counts.items():
        print(f"{table:15} sqlite={a:<8} postgres={b:<8} {'ok' if a == b else 'DIFFERENT'}")
        ok = ok and a == b
    return 0 if ok else 1


if __name__ == "__main__":
    sys.exit(main(sys.argv[1:]))
```

**`tests/test_sqlite_to_postgres.py`** – проверка переноса. Новый файл:

```python
"""The one-time SQLite -> PostgreSQL copy keeps every row, keeps a revoke, and leaves the id counters working."""

from __future__ import annotations

import os
import time
import uuid
from pathlib import Path
from zoneinfo import ZoneInfo

import pytest
from fastapi.testclient import TestClient

from app import auth
from app.db import connect, migrate
from app.main import create_app
from app.settings import Settings
from tests.test_dashboard import BOT_TOKEN, OWNER, make_key
from tools.sqlite_to_postgres import copy


def test_copy_sqlite_to_postgres(tmp_path: Path) -> None:
    base = os.environ.get("TEST_DATABASE_URL")
    if not base:
        pytest.skip("TEST_DATABASE_URL is not set")
    import psycopg

    # A realistic SQLite database: allowlist with a revoked person, two keys, pushed numbers, a log.
    settings = Settings(bot_token=BOT_TOKEN, session_secret=b"s" * 40, allowed_tg_ids=frozenset({OWNER, 5_000_000_000}),
                        db_path=tmp_path / "old.db", tz=ZoneInfo("UTC"))
    client = TestClient(create_app(settings))
    make_key(settings, "collector")
    make_key(settings, "second")
    day = time.strftime("%Y-%m-%d", time.gmtime(time.time() - 86400))
    rows = [{"key": "sales.revenue", "day": day, "value": 1234.5}, {"key": "marketing.leads", "day": day, "value": 7},
            {"key": "marketing.leads", "day": day, "value": 3, "dim": "telegram"}]
    key = make_key(settings, "pusher")
    assert client.post("/ingest", json={"source": "crm", "rows": rows},
                       headers={"Authorization": f"Bearer {key}"}).status_code == 200
    old = connect(settings.db_target)
    with old:
        old.execute("UPDATE allowed_users SET revoked_at=datetime('now') WHERE tg_id=?", (OWNER,))
    old.close()

    schema = "t_" + uuid.uuid4().hex[:10]
    with psycopg.connect(base, autocommit=True) as admin:
        admin.execute(f"CREATE SCHEMA {schema}")
        url = base + ("&" if "?" in base else "?") + f"options=-csearch_path%3D{schema}&application_name={schema}"
        try:
            fresh = connect(url)  # the dashboard was started once on PostgreSQL: the owner is on the allowlist
            migrate(fresh, [OWNER])
            fresh.close()
            counts = copy(settings.db_path, url)  # type: ignore[arg-type]
            assert all(a == b for a, b in counts.values()) and counts["metric_values"][0] == 3
            assert copy(settings.db_path, url) == counts  # type: ignore[arg-type]  # a repeat changes nothing
            new = connect(url)
            assert not auth.is_allowed(new, OWNER) and auth.is_allowed(new, 5_000_000_000)  # the revoke survived
            assert new.execute("SELECT SUM(value) FROM metric_values WHERE dim=''").fetchone()[0] == 1241.5
            assert auth.ingest_key_name(new, key, "2026-01-01 00:00:00") == "pusher"  # the key still works: same hash
            with new:  # a new key gets a fresh id (the identity counter was moved past the copied ids)
                new.execute("INSERT INTO ingest_keys(name, key_hash) VALUES ('later', 'h')")
            assert new.execute("SELECT MAX(id) FROM ingest_keys").fetchone()[0] == 4
            new.close()
        finally:
            admin.execute("SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE application_name = %s", (schema,))
            admin.execute(f"DROP SCHEMA {schema} CASCADE")
```

## 4. Поставить Supabase на свой сервер

Агент ставит Supabase по официальной инструкции: https://supabase.com/docs/guides/self-hosting/docker (код лежит в https://github.com/supabase/supabase, папка `docker`). Сначала спросите у владельца «да»: это новая служба, она занимает память и порты.

Что важно знать до установки (проверено 11.11.2026 по `docker/docker-compose.yml` и `docker/.env.example` из репозитория и по странице https://supabase.com/docs/guides/self-hosting/accessing-postgres):

- Служба с базой называется `db`, контейнер – `supabase-db`, имя базы по умолчанию `postgres` (`POSTGRES_DB`). Порт самой базы наружу не публикуется.
- Наружу по умолчанию смотрит пулер Supavisor (контейнер `supabase-pooler`). Он занимает порт `${POSTGRES_PORT}` (по умолчанию 5432, режим «сессия») и порт `${POOLER_PROXY_PORT_TRANSACTION}` (по умолчанию 6543, режим «транзакция»).
- В официальном `docker-compose.yml` эти порты записаны без адреса: `- ${POSTGRES_PORT}:5432`. Docker обычно открывает такой порт на всех интерфейсах сервера и может обойти правила обычного firewall (например, ufw). Значит, пулер по умолчанию может оказаться доступен из интернета.
- Имя пользователя через пулер – `postgres.<POOLER_TENANT_ID>` (по умолчанию `postgres.your-tenant-id`), а не просто `postgres`.
- Через REST API Supabase открыты только схемы из `PGRST_DB_SCHEMAS` (по умолчанию `public,graphql_public`). Схему дашборда `dashboard` туда не добавляйте.

Путь установки на выбор агента: быстрый скрипт из инструкции (`curl -fsSL https://supabase.link/setup.sh | sh`; агент сначала читает скрипт и только потом запускает) или ручная установка (`git clone --depth 1 --branch <тег из инструкции> https://github.com/supabase/supabase`, копирование папки `docker` в папку проекта, `.env` из `.env.example`, затем `sh utils/generate-keys.sh`). На 11.11.2026 в инструкции указан тег `self-hosted/v0.8.4`; агент берёт тег из актуальной страницы. Пароли из `.env.example` не оставлять: их заменяют сгенерированными до первого запуска.

## 5. Закрыть порты и подключить дашборд

**Порты базы – только на самом сервере.** Откройте `docker-compose.yml` в папке проекта Supabase и сделайте так:

1. У службы `supavisor` допишите `127.0.0.1:` в обе строки портов:

```yaml
    ports:
      - 127.0.0.1:${POSTGRES_PORT}:5432
      - 127.0.0.1:${POOLER_PROXY_PORT_TRANSACTION}:6543
```

2. Для прямого подключения (его рекомендует официальная страница для долгих серверных программ, вроде дашборда) добавьте службе `db` порт только на локальный адрес и другой номер хоста, чтобы не мешать пулеру:

```yaml
  db:
    ports:
      - "127.0.0.1:5433:${POSTGRES_PORT}"
```

3. Перезапустите стек (`docker compose up -d`) и проверьте: `ss -ltnp | grep -E ':(5432|5433|6543)'` показывает только `127.0.0.1`. Снаружи, с другого компьютера, `nc -vz <адрес сервера> 5432` и `5433` не должны соединяться.

Правила: порт базы не открывают в firewall, не пробрасывают наружу и не вносят в публичный DNS. Дашборд и база на одном сервере, поэтому им хватает `127.0.0.1`. Если база на другой машине, нужен закрытый канал (VPN или SSH-туннель), а не открытый порт.

**Своя роль и своя схема.** Дашборд не получает пароль суперпользователя `postgres` из `.env` Supabase. Он получает свою роль, которая видит только свою схему. Агент генерирует пароль (`python3 -c "import secrets; print(secrets.token_hex(24))"`; шестнадцатеричная строка безопасна для адреса подключения) и выполняет один раз:

```sql
-- Run once as the database owner. The password is generated, never typed or pasted into chat.
CREATE ROLE dashboard LOGIN PASSWORD '<<generated password>>';
CREATE SCHEMA dashboard AUTHORIZATION dashboard;
ALTER ROLE dashboard SET search_path = dashboard;
```

Как выполнить: записать три строки в файл с правами 600, запустить `docker exec -i supabase-db psql -U postgres -v ON_ERROR_STOP=1 < файл`, удалить файл. Команда `docker exec ... psql -U postgres` похожа на ту, что приведена в официальной инструкции (`docker compose exec db psql -U postgres -c "SHOW max_connections;"`). Роль не суперпользователь и не может создавать базы и роли. Проверка: `select rolname, rolsuper, rolcreatedb, rolcreaterole from pg_roles where rolname='dashboard'` показывает три `f`.

**Строка подключения** – в `/etc/dashboard/backend.env`, вместо `DB_PATH`:

```bash
# Direct connection through the loopback-only port (section 5). The password is the generated one.
DATABASE_URL=postgresql://dashboard:<<generated password>>@127.0.0.1:5433/postgres
```

Так как `search_path` роли указывает на схему `dashboard`, в строке схема не нужна. Это значение – секрет: файл с правами 640 (root и группа dashboard), в чат и в логи оно не попадает.

Другие варианты:
- Через пулер, режим «сессия»: `postgresql://dashboard.<POOLER_TENANT_ID>:<пароль>@127.0.0.1:5432/postgres`. Формат имени `<роль>.<tenant>` взят из официальной страницы для роли `postgres`. Работает ли он для своей роли `dashboard`, я не проверял: **агент проверяет это командой `psql '<строка>' -c 'select current_user'` и берёт прямое подключение, если команда не прошла.**
- Порт 6543 (режим «транзакция») для дашборда не используйте: по официальной странице Supavisor в этом режиме не поддерживает подготовленные запросы.

**Первый запуск.** После правки `backend.env` перезапустите службу (только после «да» владельца). При старте схема создаётся сама. Если база пустая, дальше идут демо-данные или перенос из SQLite (раздел 7).

## 7. Перенос данных из SQLite

Нужен, если дашборд уже работал на SQLite и данные жалко. Порядок:

1. Скажите владельцу, что на время переноса цифры не обновляются, и получите «да».
2. Остановите службы: `sudo systemctl stop dashboard dashboard-collector.timer`.
3. Сделайте копию файла SQLite (`sqlite3 /var/lib/dashboard/dashboard.db ".backup '/var/lib/dashboard/backup/before-postgres.db'"`).
4. Выполните перенос. Он читает файл только на чтение и не меняет его:

```bash
sudo -u dashboard bash -c 'set -a; . /etc/dashboard/backend.env; set +a; cd /opt/dashboard && venv/bin/python tools/sqlite_to_postgres.py /var/lib/dashboard/dashboard.db'
```

   Если в `backend.env` уже стоит `DATABASE_URL`, а `DB_PATH` убран, этого достаточно: путь к файлу передаётся аргументом.
5. Команда печатает по таблице «sqlite=... postgres=...»; везде должно быть `ok`, код выхода 0. Повторный запуск ничего не дублирует.
6. Запустите службы и откройте дашборд: цифры те же. Отзыв доступа, сделанный в SQLite, переносится и остаётся в силе, ключи сборщиков работают с прежними значениями.
7. Файл SQLite не удаляйте, пока не пройдёт неделя без замечаний.

Что проверено: перенос с отзывом доступа, ключами, цифрами и журналом; число строк совпало, счётчики номеров продолжили с нужного места, повтор ничего не изменил, id Telegram больше 4 байт переехал без потерь.

## 8. Резервные копии

База теперь не файл, поэтому `sqlite3 .backup` не подходит. Копию делает `pg_dump` раз в сутки. На сервере нужен клиент Postgres (пакет `postgresql-client`) версии не ниже версии сервера: в `docker-compose.yml` стоит образ `supabase/postgres:17...`, то есть версия 17. Путь команды проверьте: `command -v pg_dump`.

Файл `/etc/dashboard/backup.env` (права 640, владелец root и группа dashboard). Пароль не в командной строке, а в переменных libpq:

```bash
PGHOST=127.0.0.1
PGPORT=5433
PGUSER=dashboard
PGDATABASE=postgres
PGPASSWORD=<<generated password>>
```

`/etc/systemd/system/dashboard-backup.service` (заменяет файл из `starter.md`):

```ini
[Unit]
Description=Business dashboard database backup (pg_dump of the dashboard schema)

[Service]
Type=oneshot
User=dashboard
Group=dashboard
EnvironmentFile=/etc/dashboard/backup.env
# /var/lib/dashboard/backup is created for this user; copy its content off the server with your own tool
StateDirectory=dashboard dashboard/backup
# Dump to a temporary name and rename only after success, so a failed run never replaces a good copy
ExecStart=/usr/bin/pg_dump --schema=dashboard --format=custom --file=/var/lib/dashboard/backup/dashboard.dump.tmp
ExecStartPost=/bin/mv /var/lib/dashboard/backup/dashboard.dump.tmp /var/lib/dashboard/backup/dashboard.dump
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
```

Таймер `dashboard-backup.timer` остаётся тем же, что в `starter.md` (раз в сутки в 03:10). Копию увозят с сервера, как и раньше: это решение владельца.

**Проверка восстановления** (копия, которую никогда не восстанавливали, – не копия). Создайте пустую базу в контейнере и восстановите в неё. Команды выполняет root или пользователь с доступом к файлу копии и к Docker:

```bash
docker exec supabase-db createdb -U postgres restore_check
docker exec -i supabase-db pg_restore -U postgres --no-owner --dbname=restore_check < /var/lib/dashboard/backup/dashboard.dump
docker exec supabase-db psql -U postgres -d restore_check -Atc "select count(*) from dashboard.metric_values"
docker exec supabase-db dropdb -U postgres restore_check
```

Число строк должно совпасть с рабочей базой (`select count(*) from dashboard.metric_values` на ней).

Что проверено: `pg_dump` с переменными libpq (пароля в командной строке нет), восстановление в пустую базу (в том числе через стандартный ввод, как в команде выше) – 990 строк из 990. Сами команды `docker exec` не запускались. Саму службу systemd на проверочной машине не запускали.
